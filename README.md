[FINAL PROJECT WRITEUP](./RandySim_CS1680_FinalWriteUp.pdf)

A next-generation AI API wrapper that converts strict backend endpoints into a resilient, Natural Language API. 

By placing an LLM-powered Rust agent between your frontend and backend, frontend developers can request data using natural language (`"Get the 10 latest tasks"`), while the backend remains a standard, highly-optimized REST API.

**Key Benefits:**
* **No More Breaking Changes:** Backend API updates no longer break frontend clients. The LLM bridges the semantic gap and routes requests to the updated endpoints.
* **Rapid Frontend Development:** Request exactly the data you need in natural language.
* **End-to-End Type Safety:** Includes a TypeScript CLI that analyzes your natural language queries at build-time and generates strict TypeScript interfaces for your IDE.

---

## 🏗️ Architecture

This repository is a polyglot monorepo containing three main components:

1. **The Target (`apps/backend`):** A standard, highly-optimized REST API written in Go. It represents the "legacy" or standard backend (e.g., a Task Tracker). It is completely unaware of the AI layer.
2. **The Brain (`services/agent`):** A high-performance proxy server written in Rust. It intercepts natural language requests, uses Anthropic's Claude to map the request to the exact Go endpoint/payload, and forwards the HTTP request.
3. **The Interface (`packages/client`):** A TypeScript SDK and CLI. The CLI scans the frontend code for natural language queries, pings the Rust agent to resolve their schemas, and generates local `.d.ts` files for instant IDE autocomplete.

## Running Agent

**Prerequisites:** [Rust](https://rustup.rs) (edition 2024, stable toolchain)

**Build:**

```bash
cd services/agent
cargo build
```

**Step 1:** Analyze the Go backend once and write `routes.json`:

```bash
target/debug/agent analyze --api-key $ANTHROPIC_API_KEY --path ../../apps/backend
```

**Step 2:** Start the query server (reads `routes.json`, no re-analysis):

```bash
target/debug/agent serve --api-key $ANTHROPIC_API_KEY
# or explicitly:
target/debug/agent serve --api-key $ANTHROPIC_API_KEY --routes routes.json --port 3001
```

The server holds the API key and uses it for every incoming query. Clients send only their natural language query — no API key required in the request:

```bash
curl -X POST http://localhost:3001/query \
  -H "Content-Type: application/json" \
  -d '{"query": "get all tasks"}'
```

## 📦 Frontend Library (`packages/client`)

The `agent-client` npm package lets any TypeScript frontend make API calls using natural language. Add it to your project via the pnpm workspace:

```json
// your-app/package.json
{ "dependencies": { "agent-client": "workspace:*" } }
```

### Usage

```typescript
import { Agent } from 'agent-client'
import type { QueryResponse } from 'agent-client'

// Import the cache generated by the CLI (see below)
import agentCache from './lib/agent-cache.json'

// Construct once. Pass your backend URL and the generated cache.
// Default headers (e.g. auth token) are merged into every request.
const agent = new Agent(
  'http://localhost:8080',
  agentCache as Record<string, QueryResponse>,
  { headers: { Authorization: `Bearer ${token}` } },
)

// Natural-language API calls — no REST knowledge required
const tasks = await agent.call('Get all tasks')

// Supply path params for routes like PUT /tasks/{id}
const updated = await agent.call('Update a task', {
  pathParams: { id: 42 },
  body: { status: 'done' },
})

// Override headers per-call (merged with constructor defaults)
const data = await agent.call('Create a task', {
  headers: { Authorization: `Bearer ${freshToken}` },
  body: { title: 'Buy groceries' },
})
```

**Errors**

| Class | When thrown |
|-------|-------------|
| `AgentError` | Query string not in cache — re-run the CLI |
| `ApiError` | Backend returned a non-2xx status |

## 🛠️ CLI Tool (`packages/generate-types`)

The CLI is the bridge between dev time and runtime. It:
1. Scans your source files for every `agent.call("...")` call
2. Sends each unique query string to the Rust agent's `POST /query` once (the only LLM cost)
3. Writes a **runtime cache** (`agent-cache.json`) so the library never calls the LLM again
4. Writes **TypeScript types** (`api-types.ts`) so your IDE shows return shapes and required params

### Setup

```bash
# From the monorepo root — installs all workspace packages
pnpm install

# Build the CLI
cd packages/generate-types && pnpm build
```

### Running the CLI

```bash
# Start the Rust agent first (see "Running Agent" above), then:
cd apps/frontend
node ../../packages/generate-types/src/cli.ts \
  --agent-url http://localhost:3001 \
  --src     ./src \
  --out     ./src/lib
```

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--agent-url` | Yes | — | URL of the running Rust agent |
| `--src` | Yes | — | Directory to scan for `agent.call(...)` usages |
| `--out` | No | `./` | Directory to write generated files into |

### Output files

**`agent-cache.json`** — runtime lookup table imported by the `Agent` class:
```json
{
  "Get all tasks": { "method": "GET", "path": "/tasks", ... },
  "Update a task": { "method": "PUT",  "path": "/tasks/{id}", ... }
}
```

**`api-types.ts`** — TypeScript namespaces for every resolved call:
```typescript
/** agent.call("Get all tasks") → GET /tasks */
/** Retrieve all tasks belonging to the authenticated user */
export namespace GetAllTasks {
  export type Response = { tasks: Array<{ id: number; title: string; status: string; ... }> };
}

/** agent.call("Update a task") → PUT /tasks/{id} */
export namespace UpdateATask {
  export interface PathParams { id: number; }
  export type Body = { status: string; title: string; };
  export type Response = { task: { id: number; title: string; status: string; ... } };
}
```

### Development workflow

```
1. Write code using natural language:   agent.call("Get all tasks")
2. Run the CLI once:                    npx generate-types --agent-url ... --src ./src --out ./src/lib
3. Commit the generated cache:          git add src/lib/agent-cache.json src/lib/api-types.ts
4. Runtime is pure HTTP — no LLM:      agent.call("Get all tasks")  →  GET /tasks (cache lookup)
```

Re-run the CLI whenever you add a new `agent.call(...)` call to your source.
